# 核心

這一頁只寫跟平台無關的規則。內容來自 README 與 `templates/routine_prompt.md`、`templates/solved_list.md`。

## 已解清單

解過的洞寫在 `requests/solved_list.md`。範本在 [templates/solved_list.md](../templates/solved_list.md)。用之前先複製過去再改。

解過的洞寫在 `## 清單` 下面。一行一條。下一輪挖到同一條就不要收。也不要另寫產出檔。

四欄以 ` | ` 分開。順序固定。

`日期 | 池名 | 一句話 | 落點`

- 日期。`YYYY-MM-DD`。
- 池名。與產出第 2 行的 POOL 相同。
- 一句話。短到可以對得起來。同一件事用同一句。不要換說法。
- 落點。做完後人能找回的檔名。沒有就寫 `-`。

`## 清單` 以上都是說明。不拿來對。

範本 `## 清單` 下有兩列虛構範例。保留會被當成已解。正式用前刪掉。

每一輪開工，先讀產出庫、分支 main 上的 `requests/solved_list.md` 全文。只把 `## 清單` 之後、且符合上面四欄的列當成已解。說明段不算。

挖到的每一條先跟那些列對。一句話說的是同一件事，就當已解。丟掉。不寫產出。

對不上才寫一個產出檔。沒有新洞就不要硬湊。空著比寫重複的好。

人決定要做，而且做完之後，在 `## 清單` 下追加一行。再推回產出庫的 main。清單留在本機、沒推回 main，下一輪仍會把同一個洞收回來。

## 產出路徑

路徑：

`inbox/dig/<YYYYMMDD>_<POOL>_r<round>c<cell>.md`

例：`inbox/dig/20260929_DEMO_r1c2.md`

日期是跑題當天。八位數字。沒有橫線。一檔只放一個洞。

`POOL` 是領域池的短名。用大寫英數。短一點。跟產出檔名、已解清單的池名欄一致。具體問題由 bot 依領域那一句話自己挖。範本不附題目清單。

`r` 後面是輪次。`c` 後面是該輪的第幾格。檔名的 `c` 跟實際格號一致。

預設 4 格。cell=1 到 cell=4。人工插單指定格數時以插單為準。

輪次 round 從 1 起算。同一天若跑第二輪，round=2。檔名跟著變。

內文從第 4 行開始。用短標題加幾句話寫清楚。

- 問題是什麼。
- 為什麼現有做法還沒解決它。
- 你怎麼判斷它不在已解清單裡。

不要寫解法全文。值不值得做由人判斷。

需要別人核對事實時，另寫 `requests/factcheck/<名>.md`。不要把核對過程塞進產出檔。

## 三行檔頭

前三行只能是檔頭。第 4 行起才是內文。

1. 第 1 行。時間，含時區。例 `2026-09-29 19:02:57 +08`。
2. 第 2 行。`<POOL> round=<n> cell=<n>`。例 `DEMO round=1 cell=2`。
3. 第 3 行。第 4 行起直到檔尾的原始位元組的 SHA-256。64 字小寫十六進位。行內不要加別的字。

雜湊怎麼切。

- 把整份檔當位元組看。不要先把換行正規化。
- 數到第 3 個換行字元 `\n`。CRLF 的 `\r` 留在該行尾。不算進下一段。
- 從下一個位元組到檔尾做 SHA-256。含內文自己的換行。
- 第 3 行去掉前後空白後，等於這個雜湊。大小寫都視為同一組十六進位。寫檔時用小寫。
- 內文用 UTF-8。少於 4 行，或第 3 行不是 64 位十六進位，都算不符。

數到第 3 個 `\n`。對它後面的全部位元組做 SHA-256。

寫完就不要再改換行種類。LF 與 CRLF 的雜湊不同。範本的 [.gitattributes](../.gitattributes) 讓產出檔保持原始換行。檔頭雜湊才對得起來。

改過內文必須重算第 3 行。

## 自驗

先自驗兩件事再送。

- 檔案是完整的。沒有在句中被截斷。
- 第 3 行是按最終內文重算的。改過內文必須重算。

本機單檔：

```
python tools/verify_header.py <檔>
```

工具在 [tools/verify_header.py](../tools/verify_header.py)。不是 `OK` 就不要送。

- 印 `OK`、離開碼 0。第 3 行與第 4 行起的位元組相符。才送給人判斷。
- 印 `MISMATCH`、離開碼 1。不符。退回。不進判斷。少了行、第 3 行不是 64 位十六進位、或內文被改過，都走這條。
- 參數不是一個檔、或檔讀不到。離開碼 2。說明寫在標準錯誤。

檔在句中被截斷時，雜湊對不上，或對得上但內容明顯沒寫完。兩種都不要送去判斷。

整夾。該資料夾裡的 `*.md`。repo 根目錄的說明檔不是產出格式。整夾核對時指定 `inbox/dig` 或 `tests`。

```
python tools/verify_all.py <資料夾>
```

工具在 [tools/verify_all.py](../tools/verify_all.py)。它對資料夾內每個 `*.md` 做同一套檢查。逐檔印 `OK <檔名>` 或 `MISMATCH <檔名>`。全部 OK 才離開碼 0。有任一不符，離開碼 1。參數不是一個資料夾、資料夾裡沒有 `*.md`、或檔讀不到，離開碼 2。

[tests/fixture_ok.md](../tests/fixture_ok.md) 是一份正確夾具。[tests/fixture_mismatch.md](../tests/fixture_mismatch.md) 是同一份夾具只把內文改一個字。第 3 行仍留舊雜湊。用來對照 `MISMATCH`。

```
python tools/verify_all.py tests
```

上面這條會印一行 `OK`、一行 `MISMATCH`。離開碼 1。
