這一頁根據 2026-09-30 網頁版實查。那次只看畫面。沒有改排程。

## 每天怎麼啟動

兩條路。

### 網頁

入口在左側欄「自動化」。網址 `https://grok.com/automations`。

右上是「新自動化」。

對話框欄位。

- 名稱。
- 觸發器。可以按「新增觸發器」。
- 指示。例行題貼在這裡。下方可選連接器、技能、模型。模型當時顯示「自動」。
- 通知。電子郵件。應用程式。
- 儲存。

觸發器選項。一次。每小時。每天。每週。每月。每年。另有 Gmail「新電子郵件」。

這次沒看到選 bot 的欄位。綁 bot 的自動化可能要從 bot 對話裡建立。未驗。

清單上既有的列有這些欄。自動化名稱。排程。下一次執行。狀態。狀態看過「啟用中」。綁 bot 的列會在名稱下標 bot 名。

### 在對話裡叫它建（已驗，建議先走這條）

在 bot 的對話裡貼上例行題。叫它自己建立排程。結尾叫它回你例行名稱與下次執行時間。

2026-09-30 實測。貼上一段每天早上 7 點的例行題。bot 先回它要讀的範本。對話中出現一列「已建立例程」。它回了名稱與下次執行時間。再到左側「自動化」看。清單多了一列。排程是 Every day at 6:50 AM。狀態是啟用中。

它會自己調時間。這次說 7 點，它排在 6:50。它說它的規則落在前後 15 分內。要整點就跟它講。

建完一定去「自動化」清單看一眼。bot 說建好了不算數。清單上有那一列才算。

## 例行題貼到哪裡

網頁這條，貼在「新自動化」的指示。

對話這條，貼在跟 bot 的對話裡。

題目要寫明 owner、repo、分支 main。並寫清三步。讀該 repo 的 main 上的 `requests/solved_list.md`。未解的寫到 `inbox/dig/`。用 GitHub 連接器的建立或更新檔案工具推上 main。

格式見 [docs/core.md](../docs/core.md)。題目範本是 [templates/routine_prompt.md](../templates/routine_prompt.md)。

## 產出寫到哪

owner 與 repo 填你自己的產出庫。分支 main。

## 寫檔工具

GitHub 連接器的建立或更新檔案工具。先完成一次授權。授權成功只代表連接器開通。精確 OAuth scope 未驗。

## 通知

對話框裡有通知。電子郵件。應用程式。不接也可以。不接也不影響挖洞與收件。不要把 token 貼進聊天。也不要寫進 repo。
